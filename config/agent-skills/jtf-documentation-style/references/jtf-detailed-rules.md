# JTF Detailed Rules

この資料は、`SKILL.md` だけでは足りないときに読む詳細版です。
JTF日本語標準スタイルガイド 第3.0版の考え方を、ドキュメンテーション制作の現場で使いやすい形に整理しています。

目的は、語学的な網羅よりも、**執筆・推敲・レビューで迷いがちな判断を再現可能にすること**です。

## 1. 文体

### 1.1 本文

- 本文は敬体か常体のどちらかに統一する。
- 一般読者向けのマニュアルやヘルプでは、敬体を優先してよい。
- 技術論文風の記述や設計メモで文体上の必然がある場合に限り、常体を選ぶ。

### 1.2 見出し

- 見出しは常体または体言止めに寄せる。
- 同じ階層で、文の見出しと名詞句の見出しが乱雑に混ざらないようにする。

### 1.3 箇条書き

- 箇条書きの各項目は、本文の文体に合わせる。
- 文として閉じる形式と語句列挙の形式を混在させすぎない。
- 末尾に句点を打つなら、同じ粒度の箇条書きではそろえる。

### 1.4 図表内テキストとキャプション

- 図表内テキストとキャプションも本文に合わせる。
- 本文だけ敬体で、図表だけ常体に逃がさない。

## 2. 句読点

### 2.1 和文の句読点

- 和文本文では全角の `、` `。` を使う。
- `，` `．` は和文の句読点として使わない。

### 2.2 ピリオドとカンマ

- 半角の `.` `,` は、数値、ファイル名、URL、コード断片など欧文的な用途に限る。
- 和文のリズムを作るために `,` を使わない。

## 3. 文字種の基本

### 3.1 ひらがな

- ひらがなは全角で書く。
- 現代仮名遣いに従う。

### 3.2 漢字

- 常用漢字にゆるやかに準じる。
- 読者が読み慣れていない難字を優先しない。
- 同じ語で、簡便な書き方と難しい書き方を混在させない。

### 3.3 送りがな

- 動詞の送りがなは本則に従う。
- 名詞、複合語の送りがなも、見た目の簡略化より標準性を優先する。
- 送りがなを削って「固く見せる」方向の修正は避ける。

判断に迷う場合の典型:

- `取り消す` のように送る
- `引き渡す` のように送る

### 3.4 カタカナ

- カタカナは全角で書く。
- 半角カタカナは特殊用途を除いて使わない。

### 3.5 カタカナ語の長音

- 語尾の長音は原則省略しない。
- そのため、英語由来の用語を和文に入れるときは、短く見せるより慣用の長音あり表記を選ぶ。

例:

- `ユーザー`
- `サーバー`
- `コンピューター`

### 3.6 カタカナ複合語

- 長い複合語は、読みやすさのために中黒または半角スペースで区切る。
- ただし、既に製品名として固まっているものはその表記を優先する。
- 区切るかどうかを決めたら、同じ種類の語でそろえる。

## 4. 数字とアルファベット

### 4.1 算用数字

- 横組みでは算用数字を半角で書く。
- 値、件数、回数、日付要素、ID 付近の数値は算用数字を優先する。

### 4.2 アルファベット

- 横組みではアルファベットを半角で書く。
- 略語、コマンド名、製品名、規格名も、外部仕様がない限り半角英字を保つ。

### 4.3 桁区切りと小数点

- 桁区切りには半角カンマを使う。
- 小数点には半角ピリオドを使う。
- ただし、桁区切りカンマは用途によって省略されることがある。
- 一つの文書内で、同種の数値に異なる桁区切り方を混在させない。

### 4.4 算用数字と漢数字の使い分け

- 数えられるもの、比較するもの、測るものは算用数字を優先する。
- 慣用句、熟語、名称化した表現は漢数字が残ることがある。
- つまり、数量の問題か、語彙として固定した表現かを見て決める。

この判断が必要な典型:

- `第1章` のような番号
- 慣用句に含まれる漢数字
- 名称として固まった表現

### 4.5 助数詞

- `か月`、`か所` のような助数詞は、実務文書でぶれやすいので統一する。
- 文書内で `カ月` と `か月` を混在させない。

## 5. スペース

### 5.1 全角文字と半角文字の間

- 全角文字と半角文字の間に半角スペースを入れない。
- 見た目を整えたいだけの理由で空白を足さない。

例:

- `JTF標準`
- `Windows環境`
- `3台`

### 5.2 全角文字どうし

- 全角文字どうしの間にもスペースを入れない。

### 5.3 半角文字どうし

- 欧文をそのまま引用するときは、欧文内部の半角スペースは維持する。
- 和文の都合で欧文内部のスペースまで潰さない。

### 5.4 かっこ類と隣接文字

- かっこの前後に不要なスペースを入れない。
- とくに全角の丸かっこ、大かっこ、かぎかっこの前後を揺らさない。

## 6. 記号

### 6.1 感嘆符と疑問符

- `！` `？` は全角で書く。
- ただし和文では多用しない。
- トーン調整のために乱発しない。

### 6.2 スラッシュ

- スラッシュは全角でも半角でもありうる。
- コード、パス、URL は半角のまま扱う。
- 和文の説明文での用途は、文書内で決めてそろえる。

### 6.3 中黒

- 中黒は全角で書く。
- カタカナ複合語の区切りや並列に使う場合は、役割を増やしすぎない。

### 6.4 波線

- 波線は全角で扱う。
- 異体字が混ざりやすいので、文書群で同じ形にそろえる。

### 6.5 ハイフン

- 原則として和文では使わない。
- ただし外部仕様、型番、オプション名、英語複合語など、対象そのものの表記に含まれる場合は残す。

### 6.6 コロン

- 和文で使うなら全角コロンを基本にする。
- 多用しない。
- ラベルと値の関係が明確になる場面だけに使う。

### 6.7 セミコロン

- 原則として和文では使わない。

### 6.8 ダッシュ

- 原則として和文では使わない。
- ただし外部仕様として文字列の一部に含まれる場合は別扱いにする。

## 7. かっこと引用符

### 7.1 丸かっこ

- 和文では全角の `（ ）` を使う。

### 7.2 大かっこ

- 和文では全角の `［ ］` を使う。

### 7.3 かぎかっこ

- 和文の引用や語の取り立てには `「 」` を使う。

### 7.4 二重かぎかっこ

- 入れ子引用や書名など、用途が定まっているときに `『 』` を使う。

### 7.5 二重引用符

- 欧文引用や特定の技術的文脈では半角の `" "` を使う。
- 和文で多用しない。

### 7.6 中かっこ、山かっこ、一重引用符

- `{ }` `＜ ＞` `' '` は原則として和文では使わない。
- コード、テンプレート、外部仕様として必要なときだけ残す。

## 8. 単位

### 8.1 単位系

- 単位系は、文書単位で統一する。
- JTF は JIS の量と単位の規格に従う方向を採る。

### 8.2 単位記号と名称

- 英字記号とカタカナ名称を混在させると読みにくくなることがある。
- どちらを主に使うかを先に決める。
- 同じ種類の量で `kg` と `キログラム` を無秩序に混在させない。

### 8.3 個別単位で揺れやすいもの

揺れやすいので、文書全体でどれを採るか固定する。

- 時間、時刻
- 長さ
- 質量
- 面積、体積
- 電気
- 温度
- 周波数
- 速度
- 伝送速度
- 割合
- 角度
- 記憶容量
- 通貨

### 8.4 容量と通信量

- `b` と `B` の違いを曖昧にしない。
- ビットとバイト、通信速度とデータサイズを混同しない。
- `KB` と `Kb` のような大小文字差は意味差を持つので、見た目で丸めない。

## 9. 機械チェックと人手レビュー

JTF 日本語スタイルチェッカーの公開情報を見ると、機械チェックしやすい項目と、そうでない項目が分かれる。
運用ではこれを意識すると効率がよい。

### 9.1 機械で見つけやすい項目

- `、。` の有無
- 全角と半角の混在
- 半角カタカナ
- 長音抜けの一部
- 常用漢字外の一部
- 不要スペース
- 一部の記号

### 9.2 人手で見るべき項目

- 敬体と常体の統一
- 見出しの文体
- 箇条書きの粒度
- 同一概念の表記ゆれ
- 数字と漢数字の文脈判断
- コロンやスラッシュの使い分け
- 単位と意味の整合

## 10. 実務での判断テンプレート

迷うたびに長く議論しないよう、次の順で決める。

1. これは外部仕様で固定されているか
2. 既存文書群に正表記があるか
3. JTF の基本ルールで決まるか
4. JTF の詳細ルールで決まるか
5. それでも揺れるなら、今後も再利用しやすい側を採り、文書全体に波及させる

## 11. レビュー用チェックリスト

- 本文の文体は一つにそろっているか
- 見出し、箇条書き、キャプションが本文から浮いていないか
- `、。` と `，．` が混在していないか
- 長音ありと長音なしが混在していないか
- 送りがなが省略体と本則で揺れていないか
- 同じ語が漢字形とかな形で揺れていないか
- 全角数字と半角数字が混在していないか
- 桁区切りと小数点がそろっているか
- 不要な半角スペースが紛れ込んでいないか
- 記号の全角半角が用途ごとにそろっているか
- かっこ、引用符の種類が役割に合っているか
- 単位記号、通貨、割合、容量の意味が崩れていないか

## 12. 使い分けで誤りやすい場面

### 12.1 英語風の見た目に寄せたくなる場面

- 半角スペースを足したくなる
- コロンやハイフンを多用したくなる
- 長音を落として短く見せたくなる

この方向は、和文としての一貫性を壊しやすい。

### 12.2 固有表記を一般規則で潰してしまう場面

- 製品名
- UI ラベル
- API 名
- 型番
- 法令名
- 規格名

これらは JTF より外部仕様を優先する。

### 12.3 単位を見た目だけでそろえてしまう場面

- `b` と `B`
- `%` と `％`
- `km/h` と日本語表記

見た目ではなく、意味と文書全体の選択でそろえる。
