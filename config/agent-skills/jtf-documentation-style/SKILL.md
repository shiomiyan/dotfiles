# JTF Documentation Style

JTF日本語標準スタイルガイド 第3.0版（2019-08-20）を、ドキュメンテーション制作の実務にそのまま使える形に落としたスキルです。
目的は、表現の巧拙を競うことではなく、**表記の揺れを減らし、読者にとって予測可能な日本語を保つこと**です。

JTF 原典は翻訳用だが、和文の README、運用手順書、ヘルプ、マニュアル、UI 説明、技術記事の推敲にも有効です。
このスキルは、特に**表記統一**と**レビュー時の判断基準の固定**に使います。

原典:
`https://www.jtf.jp/pdf/jtf_style_guide.pdf`

JTF の公開案内:
`https://www.jtf.jp/tips/styleguide`

JTF 日本語スタイルチェッカー:
`https://www.jtf.jp/jp/style_guide/jtfstylechecker.html`

## このスキルが扱うこと

- 文体の統一
- 句読点と記号の使い方
- ひらがな、漢字、カタカナ、アルファベット、数字の表記
- 送りがな、長音、複合語の区切り方
- 全角半角とスペースの扱い
- かっこ、引用符、単位の扱い
- 文書レビュー時のチェック観点

## このスキルが扱わないこと

- 文章の論理構成そのもの
- 説明順序や情報設計
- 原文の意味忠実性そのもの
- 製品、ブランド、法令、規格が外部仕様として固定している固有表記の上書き

これらは別に判断する。
JTF と外部仕様が衝突したら、原則として**外部仕様を優先**する。

## 基本原則

- 文書ごとに表記方針を一つに固定する。
- 著者の好みより、標準的で再利用しやすい表記を優先する。
- 迷ったら、例外を増やすより JTF の規範に寄せる。
- 一度決めた表記は、同一文書だけでなく近接文書にも波及させる。
- 目視だけで覚えようとせず、必要なら機械的に点検する。

## 最初に固定すること

執筆や推敲を始める前に、次を決める。

1. 本文の文体は敬体か常体か
2. 対象読者は一般読者か専門読者か
3. 用語の正表記は何か
4. 外部仕様として固定される表記があるか
5. 単位、数値、記号の表記をどこまで統一対象に含めるか

一般向けドキュメントでは、特別な理由がなければ敬体を既定値にする。

## 最初に読むべき詳細資料

この `SKILL.md` は運用手順と優先順位を示す。
実際の判断は、必要に応じて次を読む。

- 詳細な規則、優先順位、レビュー観点:
  [references/jtf-detailed-rules.md](references/jtf-detailed-rules.md)

語ごとの細則、数字と漢数字の境界、記号の可否、単位の扱いまで詰めるときは、この参照資料を開く。

## 作業手順

### 1. 既存の正を探す

まず、同じ文書群の中に既存の正表記があるかを調べる。
既存の用語集、製品 UI、過去版マニュアル、レビュー済み文書があれば、それを優先する。

### 2. JTF に寄せて基準を決める

既存の正がない場合は、JTF の既定ルールに寄せる。
既定ルールだけで決まらないときは、`references/jtf-detailed-rules.md` を読む。

### 3. 文書全体を正規化する

個別に直して終わらせず、同じ種類の揺れをまとめて直す。
特に次は局所修正で終えない。

- 文体
- 句読点
- 長音
- 全角半角
- スペース
- 数字
- 単位
- 同一概念の表記揺れ

### 4. 機械的な観点で見直す

最後に、意味の正しさとは別に、表記ルールとして揺れていないかを確認する。
機械的に見つけやすい箇所は、JTF 日本語スタイルチェッカー相当の観点で洗う。

## 12 の既定ルール

JTF の基本ルールとして、最低限これを守る。

1. 本文は敬体または常体のどちらかに統一する。
2. 句読点は `、` と `。` を使う。
3. 常用漢字表にある漢字を優先する。
4. 動詞の送りがなは本則に従う。
5. カタカナ語の語尾の長音は省略しない。
6. 長いカタカナ複合語は、中黒または半角スペースで区切る。
7. 漢字、ひらがな、カタカナは全角で書く。
8. 横組みでは数字とアルファベットを半角で書く。
9. 記号類は原則として全角で書く。
10. 半角文字と全角文字の間に半角スペースを入れない。
11. ピリオド、カンマ、スペースは半角で書く。
12. 単位の表記を統一する。

## 判断の優先順位

規則が衝突しそうなときは、次の順で決める。

1. 法令、規格、製品 UI、ブランドなどの外部仕様
2. その文書群で既に確定している用語集やスタイル
3. JTF の基本ルール
4. JTF の個別細則
5. 読者の理解を損なわない範囲での局所判断

局所判断をするときも、単発の例外で終えず、同種の表記に波及させる。

## よくある実務判断

### 文体

- 本文は敬体か常体のどちらかに統一する。
- 見出しは常体または体言止めに寄せる。
- 箇条書き、図表内テキスト、キャプションは本文に合わせる。
- 文体の混在を、強調や親しみやすさのために許容しない。

### 和文の句読点

- 和文本文では `、` と `。` を使う。
- `，` と `．` を和文の句読点として使わない。
- 小数点や桁区切りのような数値用途では、半角の `.` `,` を使う。

### 漢字とかな

- 難解な漢字や表外漢字を優先しない。
- 読みやすさと実務での一般性を優先する。
- 送りがなを削って固い印象にしない。
- 同じ語を、漢字形とかな形で混在させない。

### カタカナ語

- 長音は原則として落とさない。
- 長い複合語は、読みやすさのために中黒または半角スペースで区切る。
- 半角カタカナは特殊用途を除いて使わない。

### 数字と漢数字

- 数えられる量、値、件数、回数、ID 周辺の数値は算用数字を優先する。
- 慣用句や名称化した表現では漢数字が残ることがある。
- 数量なのか名称なのかを見て決める。

### 全角半角とスペース

- 全角文字と半角文字の間に半角スペースを入れない。
- 全角文字どうしの間にも空白を入れない。
- 欧文そのものを引用するときは、欧文内部の半角スペースは保持する。
- かっこ類と隣接する文字の間にも不要な空白を入れない。

### 記号

- 感嘆符と疑問符は全角にするが、多用しない。
- ハイフン、セミコロン、ダッシュ、中かっこ、山かっこ、一重引用符は、和文では原則避ける。
- コロンは全角を基本にするが、多用しない。
- 二重引用符は半角を使う。

### 単位

- 単位系を混在させない。
- 記号表記とカタカナ表記を不用意に混在させない。
- 数値、単位、桁区切り、小数点の書式を文書全体でそろえる。

## レビュー時の進め方

レビューでは、内容レビューと表記レビューを分ける。
表記レビューでは次の順で見る。

1. 文体の混在
2. 同一概念の表記揺れ
3. 句読点、長音、全角半角
4. 数字、単位、記号
5. かっこや引用符の選択

細かい表記が大量に揺れている文書では、局所コメントを増やすより、先に全体方針を確定して一括修正する。

## 原典や詳細資料を必ず見る場面

次の場面では、`references/jtf-detailed-rules.md` を読み、それでも迷えば JTF 原典を開く。

- ひらがなと漢字の使い分けを語ごとに詰めたい
- 送りがなの本則を厳密に確認したい
- 数字と漢数字の境界が文脈依存で揺れる
- コロン、スラッシュ、ダッシュ、引用符の選択に迷う
- 単位、割合、通貨、容量、速度などの個別表記を厳密にそろえたい
- 機械チェック可能なルールと、人手レビューが必要なルールを切り分けたい

## 実行時の心得

- 例外を作る前に、既存の正と JTF のどちらに寄せるかを明示する。
- 一つの直しが他の箇所にも波及するかを必ず考える。
- 見た目の好みで空白や記号を足さない。
- 和文の標準性を壊してまで英語風の見た目に寄せない。
- 精密さが必要でも、独自流儀を増やしてはいけない。
